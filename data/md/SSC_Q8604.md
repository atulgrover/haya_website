#### SSC/Q8604: RPA  Developer
Brief Job Description
This qualification trains individuals to become RPA Developers, covering the complete RPA lifecycle. It
begins with foundational knowledge of RPA, business process analysis, and bot design principles,
progressing to hands-on development using various tools and programming languages. The curriculum
emphasizes testing, deployment, and monitoring techniques, including security and infrastructure
considerations. Advanced topics such as AI integration and cloud-based solutions are also included. Finally,
the qualification integrates essential employability skills training to prepare graduates for the workforce
Personal Attributes
They must possess strong interpersonal skills to coordinate with other team members and achieve project
success. They should also have a basic understanding of various technologies.
Applicable National Occupational Standards (NOS)
Compulsory NOS:
1. SSC/N8601: Identify and analyse business processes suitable for automation
2. SSC/N8603: Establish a functional design of the automation solution
3. SSC/N8607: Define infrastructure requirements for the Robotic Process Automation solution
4. SSC/N8614: Design & Develop the bot as per design documents
5. SSC/N8615: Develop test cases for the bot
6. SSC/N8616: Identify and fix bugs in the bot
7. SSC/N8618: Ensure that processes are being triggered as intended and handle process exceptions
8. SSC/N8622: Review post deployment analytics & provide process improvement information to appropriate stakeholders
9. SSC/N8629: New Technology application in RPA
10. DGT/VSQ/N0102: Employability Skills (60 Hours)

#### SSC/N8601: Identify and analyse business processes suitable for
automation
Description
This unit is about analyzing business processes and identifying processes suitable for automation
Scope
The scope covers the following :
RPA Introduction
Process Mapping
RPA Suitabilty Assesment
Value Identification & ROI Calculation
Stakeholder Analysis
#### Elements and Performance Criteria
RPA Introduction
#### To be competent, the user/individual on the job must be able to:
- PC1. Understand the RPA, Intelligent automation ,hyperautomation and Agentic AI
- PC2. Understand the RPA Lifecycle and its use cases
Process Mapping
#### To be competent, the user/individual on the job must be able to:
- PC3. Map a real-world business process using various techniques (flowcharts, BPMN)
RPA Suitabilty Assesment
#### To be competent, the user/individual on the job must be able to:
- PC4. Evaluate the mapped process against the criteria for RPA suitability
Value Identification & ROI Calculation
#### To be competent, the user/individual on the job must be able to:
- PC5. Estimate the potential ROI (cost estimations,time savings, error reduction) from automation
Stakeholder Analysis
#### To be competent, the user/individual on the job must be able to:
- PC6. Identify key stakeholders impacted by the automation of the chosen process

business requirements

#### SSC/N8603: Establish a functional design of the automation solution
Description
This unit is about defining a functional design of the automation solution by refining business processes,
creating Process Design Document and defining other Robotic Process Automation milestone deliverables
Scope
The scope covers the following :
Reengineering Processes
Creating Process Design Document
Creating other Robotic Process Automation Milestone Deliverables
#### Elements and Performance Criteria
Reengineering processes
#### To be competent, the user/individual on the job must be able to:
- PC1. Break down the selected business process(es) to granular level of detail
- PC2. Re-engineer the identified process to improve automation potential using design thinking
and other frameworks
Creating Process Definition Document
#### To be competent, the user/individual on the job must be able to:
- PC3. Agree with the development team on the level of detail needed by them
- PC4. Conduct workshops and partner with SMEs to create process flows and process maps of 'as-
is' and 'to-be' processes
- PC5. Define if the bot in a given process is attended or unattended
- PC6. Prepare the Process Definition/Design Document (PDD) containing essential elements of 'as-
is' process description, 'to-be' process description and exceptions using appropriate tool
- PC7. Create a checklist to ensure the documentation is accurate and consistent
- PC8. Get the Process Design Document validated by various business and technical stakeholders
Creating Other Robotic Process Automation milestone deliverables
#### To be competent, the user/individual on the job must be able to:
- PC9. Define Business Continuity Plan (BCP), Non functional requirements (NFR) for the whole RPA
program and functional requirement questionnaire (FRQ)
- PC10. Coordinate the review and submission of RPA milestone deliverables (i.e. Solution Design
Document (SDD), Operational Impact Document (OID), Process Design Instruction (PDI),
Object Design Instructions (ODI), Technical Design Document (TDD))
- PC11. Maintain automation documentation according to standards, best practices and standard
operating procedures

#### SSC/N8607: Define infrastructure requirements for the Robotic Process
Automation solution
Description
This unit is about defining the infrastructure requirements for the Robotic Process Automation solution
Scope
The scope covers the following :
Infrastructure Requirements
Security Requirements
Other Requirements
Infrastructure Maintenance
Business Continuity
#### Elements and Performance Criteria
Infrastructure Requirements
#### To be competent, the user/individual on the job must be able to:
- PC1. Identify suitable infrastructure in network, storage, and compute, such as on-premise
storage/cloud/hybrid
- PC2. Define the environments and corresponding runtime resource
- PC3. Gather specifications on databases, installation modes, servers, control room architecture and
communication handshake between bot agent and control room from appropriate teams
- PC4. Evaluate if the solution is non-invasive on existing infrastructure landscape and network/
security architecture
Security Requirements
#### To be competent, the user/individual on the job must be able to:
- PC5. Specify the security requirement encompassing permission, user access, protocols,
provisioning of bot IDs, role-based access controls etc, for both unattended and monitored bots
Other Requirements
#### To be competent, the user/individual on the job must be able to:
- PC6. Define other prerequisites such as licenses, update/upgrade policies, etc
Infrastructure Maintenance
#### To be competent, the user/individual on the job must be able to:
- PC7. Define downtime schedule and activities during downtime such as restart of runtime
resources, clearing log files, check space etc.
Business Continuity
#### To be competent, the user/individual on the job must be able to:
- PC8. Prepare a plan for high availability and disaster recovery

| Sector | Sector is a conglomeration of different business operations having similar business and interests. It may also be defined as a distinct subset of the economy whose components share similar characteristics and interests. |
| --- | :---: |
| Sub-sector | Sub-sector is derived from a further breakdown based on the characteristics and interests of its components. |
| Occupation | Occupation is a set of job roles, which perform similar/ related set of functions in an industry. |
| Job role | Job role defines a unique set of functions that together form a unique employment opportunity in an organisation. |
| Occupational Standards (OS) | OS specify the standards of performance an individual must achieve when carrying out a function in the workplace, together with the Knowledge and Understanding (KU) they need to meet that standard consistently. Occupational Standards are applicable both in the Indian and global contexts. |
| Performance Criteria (PC) | Performance Criteria (PC) are statements that together specify the standard of performance required when carrying out a task. |
| National Occupational Standards (NOS) | NOS are occupational standards which apply uniquely in the Indian context. |
| Qualifications Pack (QP) | QP comprises the set of OS, together with the educational, training and other criteria required to perform a job role. A QP is assigned a unique qualifications pack code. |
| Unit Code | Unit code is a unique identifier for an Occupational Standard, which is denoted by an ‘N’ |
| Unit Title | Unit title gives a clear overall statement about what the incumbent should be able to do. |
| Description | Description gives a short summary of the unit content. This would be helpful to anyone searching on a database to verify that this is the appropriate OS they are looking for. |
| Scope | Scope is a set of statements specifying the range of variables that an individual may have to deal with in carrying out the function which have a critical impact on quality of performance required. |
