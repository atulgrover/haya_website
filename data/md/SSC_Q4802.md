SSC/Q4802: Software Test Engineer
Brief Job Description
A Software Test Engineer is responsible for designing, developing, and coordinating test plans to ensure
software quality and compatibility across diverse environments, including programs, hardware, operating
systems, and networks. This role involves performing both scheduled and ad-hoc testing, conducting
detailed software compatibility assessments, and identifying potential defects.
Personal Attributes
This role requires strong analytical skills, attention to detail, and the ability to work independently or within
teams. The individual must demonstrate logical thinking, effective decision-making, and clear
communication while being proactive and result oriented.
Applicable National Occupational Standards (NOS)
Compulsory NOS:
- 1. SSC/N4801: Develop Test Plans for Software Products/ Applications/Modules
- 2. DGT/VSQ/N0102: Employability Skills (60 Hours)

SSC/N4801: Develop Test Plans for Software Products/
Applications/Modules
Description
This National Occupational Standard (NOS) outlines the key responsibilities and competencies required for
developing test plans for software products, applications, and modules, ensuring thorough testing and
quality assurance across various environments.
Scope
The scope covers the following :
Analyze Requirements
Define Test Objectives
Design Test Cases
Testing Frameworks and Tools
Develop the Test Plan Document
Review and Validate the Test Plan
Documentation and Reporting
Manage Test Plan Updates
Generative AI in Software Testing
Adhere to Organizational Standards
Elements and Performance Criteria
Analyze Requirements
To be competent, the user/individual on the job must be able to:
PC1. review and understand software product/application/module specifications and requirements
documents.
PC2. identify critical functionalities and performance criteria based on client and project needs.
PC3. assess technical feasibility and potential challenges for the testing process.
Define Test Objectives
To be competent, the user/individual on the job must be able to:
PC4. establish clear testing objectives, including functional, non-functional, and performance
testing requirements.
PC5. prioritize test scenarios based on their impact, complexity, and risk assessment.
PC6. identify compatibility and compliance standards to be addressed during testing.
Design Test Cases
To be competent, the user/individual on the job must be able to:
PC7. create and modify high-level scenarios and detailed test cases, ensuring coverage of
positive, negative, and boundary scenarios, and including input conditions, execution steps,
and expected outcomes.
PC8. utilize reusable and modular testing techniques for scalability and efficiency, accessing test
cases, scripts, and tools from the organization's knowledge base.

Testing Frameworks and Tools
To be competent, the user/individual on the job must be able to:
PC9. select and implement appropriate manual and automated testing tools (e.g., Selenium,
Appium, JUnit) based on project requirements.
PC10. design tests using modern frameworks such as TestNG, Cucumber, or PyTest to ensure
scalability and efficiency in testing.
Develop the Test Plan Document
To be competent, the user/individual on the job must be able to:
PC11. prepare a comprehensive test plan document detailing scope, objectives, timelines, and
resources required.
PC12. specify testing tools, environments, and data sets to be used.
PC13. outline roles and responsibilities of team members involved in the testing process.
Review and Validate the Test Plan
To be competent, the user/individual on the job must be able to:
PC14. review and rework the test plan, test cases, and/or automated scripts with consultation from
the supervisor or industry experts.
PC15. submit the test plan, test cases, and/or automated scripts for approval by experts.
PC16. validate the test plan for completeness, feasibility, and adherence to quality standards.
Documentation and Reporting
To be competent, the user/individual on the job must be able to:
PC17. create detailed reports for test execution, results, and defect tracking, providing clear and
actionable insights.
PC18. use defect tracking tools like Jira, Bugzilla, or Azure DevOps to report and monitor software
defects, ensuring timely resolution.
Manage Test Plan Updates
To be competent, the user/individual on the job must be able to:
PC19. monitor changes in product/application requirements and update the test plan accordingly.
PC20. update the organization’s knowledge base with inputs for designing tests and ensure
consistency in implementation.
PC21. communicate updates to stakeholders and maintain version control for test plan
documentation.
Generative AI in Software Testing
To be competent, the user/individual on the job must be able to:
PC22. understand the basic concepts and principles of Generative AI, including its potential
applications in software testing and quality assurance
PC23. identify and explore use cases where Generative AI can enhance software testing, such as
test case generation, automated bug detection, and test script optimization
PC24. design and optimize effective prompts for Generative AI tools used in test automation,
ensuring the accuracy and relevance of generated test cases and scripts.

Knowledge and Understanding (KU)
The individual on the job needs to know and understand:
KU1. the organization's policies, procedures, and processes for designing tests for software
products/applications/modules, including individual roles and responsibilities in the testing
lifecycle.
KU2. the application and use of software testing tools, both manual and automated, including
when and how to use tools like Selenium, Appium, JUnit, TestNG, and others for specific
testing requirements
KU3. the different sources of information available for designing tests and how to access these,
such as internal knowledge bases, product documentation, user stories, and requirement
specifications
KU4. the approval process for software products/applications/modules/tests, including who needs
to approve test plans, test cases, and scripts and how to submit them for approval.
KU5. how to identify issues that may occur with the testing requirements and how to address
these, including gaps, ambiguities, or misalignments in the requirements.
KU6. the concept and principles of designing tests and ensuring adequate code coverage through
appropriate testing strategies, such as boundary value analysis, equivalence partitioning,
and error guessing.
KU7. how to create suitable tests for applications and how to assess their suitability for
automation.
KU8. how to access, create, and modify different types of test materials, including high-level
scenarios, test cases, automated scripts, test data, and test plans.
KU9. the scripting/programming languages to understand test cases and current practices in the
industry.
KU10. the industry-standard test case design practices and test automation frameworks.
KU11. how to track and manage defects through defect tracking tools (e.g., Jira, Bugzilla, Azure
DevOps).
KU12. the importance of effective defect lifecycle management.
KU13. the need for regular maintenance of test scripts, especially in automated testing, to keep
them up to date with changing application features and functionalities
KU14. how to report and document the results of tests, including creating detailed test execution
reports and defect reports.
KU15. how to summarize test results and communicate findings with stakeholders.
KU16. the best practices for testing in different environments, including compatibility testing across
multiple browsers, operating systems, and hardware configurations.
KU17. the testing strategies for both functional and non-functional requirements, ensuring that
performance, security, and usability aspects are also covered in test plans
KU18. the various test methodologies, such as Agile, Waterfall, and DevOps
