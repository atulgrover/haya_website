SSC/Q8702: Blockchain Architect
Brief Job Description
The Blockchain Architect is responsible for designing, developing, and maintaining blockchain-based
systems. This role involves defining project requirements, designing system architecture, and developing
smart contracts focusing on security. The developer must assess vulnerabilities, ensure scalability, and
integrate blockchain solutions with existing systems. Additionally, they establish governance models and
adhere to best practices in blockchain management
Personal Attributes
Individuals in this job role must have coordination skills to interact with multiple stakeholders as well as
team members and to ensure project success. They must possess good communication skills to articulate
their arguments and persuade others. They should have a professional commitment to constantly update
their knowledge on the latest technological updates.
Applicable National Occupational Standards (NOS)
Compulsory NOS:
- 1. SSC/N8732: Define project requirements, conduct feasibility studies, and select appropriate
blockchain platform.
- 2. SSC/N8733: Design overall system architecture, including data flow, consensus mechanism, and
node structure.
- 3. SSC/N8734: Develop high-level smart contract specifications and security strategies & deploy the
blockchain solution
- 4. SSC/N8735: Identify vulnerabilities in various layers of blockchain and develop security features for
them.
- 5. SSC/N8736: Plan for scalability and integration with existing systems
- 6. SSC/N8737: Establish governance models and best practices
- 7. DGT/VSQ/N0102: Employability Skills (60 Hours)

SSC/N8732: Define project requirements, conduct feasibility studies, and
select appropriate blockchain platform.
Description
This unit is about evaluating the feasibility of blockchain adoption and formulating an initial roadmap
Scope
The scope covers the following :
Define Project Requirements
Conduct Feasibility Study
Select Appropirate Blockchain Platform
Create Implementation Roadmap
Elements and Performance Criteria
To be competent, the user/individual on the job must be able to:
PC1. Identify the specific business problem or use case (e.g. product tracability,digital
identity,NFT,insurance claim processing etc.) you want to address with blockchain
PC2. Outline functional and non-functional requirements for the solution
PC3. Define key objectives, success criteria, and expected outcomes
PC4. Determine privacy, security, scalability and performance needs
PC5. Identify integration requirements with existing systems
PC6. Define regulatory compliance needs
PC7. Analyze if blockchain is truly needed or if traditional databases would suffice
PC8. Evaluate technical feasibility - can blockchain meet performance/scalability needs?
PC9. Assess economic feasibility - costs vs benefits, ROI analysis
PC10. Examine operational feasibility - impact on existing processes/systems
PC11. Evaluate legal/regulatory feasibility - compliance with relevant regulations
PC12. Analyze organizational readiness - skills, culture, change management needs
PC13. Determine public vs private blockchain needs
PC14. Evaluate consensus mechanisms (PoW, PoS, etc.)
PC15. Assess programming languages and development tools
PC16. Compare transaction speeds and costs
PC17. Evaluate smart contract capabilities
PC18. Assess interoperability with other systems
PC19. Compare security features and track record
PC20. Evaluate community support and ecosystem
PC21. Consider adoption rates and long-term viability
PC22. Define project phases and milestones
PC23. Allocate resources and budget

SSC/N8733: Design overall system architecture, including data flow,
consensus mechanism, and node structure.
Description
This NOS is about developing the overall system architechture for the blockchain solution
Scope
The scope covers the following :
System Architecture Design
Network layer
Consensus layer
Data layer
Execution layer
Application Layer
Elements and Performance Criteria
To be competent, the user/individual on the job must be able to:
PC1. Design the overall system architecture, including on-chain and off-chain components
PC2. Design the network architecture that supports the blockchain application, including node
configuration, network protocols, and communication channels
PC3. Evaluate different consensus mechanisms like Proof of Work (PoW), Proof of Stake (PoS), or
Delegated Proof of Stake (DPoS) based on security, decentralization, scalability, and energy
efficiency
PC4. Define the structure and flow of blockchain data within the blockchain network
PC5. Define the execution layer for processing of transactions and smart contracts.
PC6. Define the application layer, it provides interfaces for users and applications to interact with
the blockchain.
Knowledge and Understanding (KU)
The individual on the job needs to know and understand:
KU1. Deep understanding of blockchain fundamentals, including consensus mechanisms,
cryptography, and distributed ledger technology
KU2. Proficiency in creating high-level and low-level system designs
KU3. Understanding of distributed computing principles
KU4. Knowledge of networking protocols and standards
KU5. Proficiency in designing both on-chain and off-chain data storage solutions
KU6. Expertise in cryptographic protocols and their implementation
KU7. Proficiency in designing RESTful APIs and GraphQL interfaces
KU8. Ability to design high-performance blockchain systems

SSC/N8734: Develop high-level smart contract specifications and security
strategies & deploy the blockchain solution
Description
This NOS is about high-level smart contract specifications and security strategies
Scope
The scope covers the following :
Determine Contract Architecture
Implement Security Strategies
Elements and Performance Criteria
To be competent, the user/individual on the job must be able to:
PC1. Define Contract Purpose and Functionality (For eg.Token creation and
management,Decentralized exchange mechanisms,Supply chain tracking,Decentralized
finance (DeFi) protocols)
PC2. Identify key components and their interactions
PC3. Determine inheritance patterns and contract relationships
PC4. Define the core data that the contract will manage
PC5. Specify roles and permissions within contract
PC6. Implement Secure Coding Practices
PC7. Write extensive unit tests for all functions
PC8. Conduct multiple rounds of audits
PC9. Implement Fail-Safe Mechanisms
PC10. Ensure the security of any off-chain elements interacting with the contract
PC11. Implement real-time monitoring for suspicious activities
PC12. Use multi-signature wallets for critical functions and deploy the solution
Knowledge and Understanding (KU)
The individual on the job needs to know and understand:
KU1. Deep understanding of blockchain fundamentals, including consensus mechanisms,
cryptography, and distributed ledger technology
KU2. Proficiency in smart contract programming and deployment
KU3. Experience with development environments like Remix, Truffle, Hardhat, or Brownie
KU4. Familiarity with Web3.js, ethers.js, or other blockchain interaction librarie
KU5. Understanding of version control system
KU6. Knowledge of secure coding practices and vulnerability assessment
KU7. Experience with smart contract auditing and risk assessment

SSC/N8735: Identify vulnerabilities in various layers of blockchain and
develop security features for them.
Description
This unit is about securing the blockchain solution
Scope
The scope covers the following :
Secure the core blockchain
Create relevant documents and reports
Elements and Performance Criteria
To be competent, the user/individual on the job must be able to:
PC1. Collaborate with the core blockchain development team to secure various layers of
blockchain (data layer, network layer, consensus layer, incentive layer, smart contract layer,
etc.) and incorporate security features in them
PC2. Develop security monitoring and management controls for core blockchain
PC3. Conduct security and vulnerability asessments, including penetration testing, to identify risks
and weaknesses in core blockchain
PC4. Perform security testing to ensure that proper cryptographic encryption and consensus
mechanism is followed for each transaction through individual nodes
