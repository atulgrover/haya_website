SSC/Q8403: Application Developer - Web & Mobile
Brief Job Description
An Application Developer - Web and Mobile designs, develops, and maintains innovative applications that
fulfill user needs and business objectives. The role involves managing the entire application lifecycle,
ensuring efficient workflows for continuous integration and delivery. The individual collaborates with cross-
functional teams to gather requirements, conducts testing, and implements enhancements to optimize
performance and user experience. The person also provides ongoing support for existing applications.
Personal Attributes
The individual should possess strong communication skills to collaborate effectively with different
stakeholders. The person should have problem-solving skills, attention to detail, adaptability to changing
requirements, and the ability to work independently and as part of a team. A proactive attitude and a
passion for technology are also essential in the role.
Applicable National Occupational Standards (NOS)
Compulsory NOS:
- 1. SSC/N8417: Implement DevSecOps practices for secure application development
- 2. SSC/N8451: Implement Continuous Integration and Continuous Deployment (CI/CD) practices
- 3. SSC/N8125: Develop tests or simulations for end-to-end QA of systems
- 4. SSC/N8418: Fix application bugs and improve application performance
- 5. SSC/N8323: Monitor and manage cloud applications and the deployed systems
- 6. SSC/N8452: Optimize Revenue, Security, and Accessibility in Web and Mobile Products
- 7. DGT/VSQ/N0102: Employability Skills (60 Hours)
Electives(mandatory to select at least one):
Elective 1: Front-end Web Development
This unit is about developing web application for different platforms keeping in mind the different
requirements of the application/ solution
- 1. SSC/N8414: Develop a user-friendly web app aligned with functional, non-functional, and UX
requirements

SSC/N8417: Implement DevSecOps practices for secure application
development
Description
This unit is about integrating security into the application development lifecycle through DevSecOps
practices. It includes managing secure code repositories, ensuring security compliance during
development, and conducting security assessments to identify vulnerabilities
Scope
The scope covers the following :
Secure version control and source code management
Security compliance and auditing
Security in deployment pipelines
Elements and Performance Criteria
• Secure version control and source code management
To be competent, the user/individual on the job must be able to:
PC1. maintain and secure the repository, ensuring appropriate access controls and backup
procedures for managing application source code
PC2. manage changes to the application code/source code through a version control system,
tracking all changes and contributions
PC3. implement policies for code review, tagging, and secure merging to minimize vulnerabilities in
the development process
PC4. integrate version control systems with project management tools, streamlining workflow and
collaboration across teams
Security compliance and auditing
To be competent, the user/individual on the job must be able to:
PC5. conduct security reviews of application source code, including vulnerability scanning and
static code analysis
PC6. integrate security tools into the DevSecOps pipeline to automate security checks throughout
the development lifecycle
PC7. document security practices and maintain compliance with industry standards (e.g., ISO/IEC
27001)
Security in deployment pipelines
To be competent, the user/individual on the job must be able to:
PC8. ensure security measures are applied during deployment, such as encryption, access
management, and firewall configuration
PC9. conduct penetration testing and security audits before and after deployment to identify and
mitigate risks
Knowledge and Understanding (KU)

SSC/N8451: Implement Continuous Integration and Continuous
Deployment (CI/CD) practices
Description
This unit focuses on the automation of the build, testing, and deployment of applications using CI/CD
pipelines
Scope
The scope covers the following :
Build and test automation
CI/CD pipeline management
Deployment automation
Elements and Performance Criteria
Build and test automation
To be competent, the user/individual on the job must be able to:
PC1. manage application environment variables and configurations for target environments
PC2. automate build and testing using scripts, tools, and test frameworks to ensure consistency and
efficiency
PC3. integrate automated tests into the CI pipeline to detect errors early in the development cycle
CI/CD pipeline management
To be competent, the user/individual on the job must be able to:
PC4. implement and manage CI/CD pipelines, ensuring a smooth and automated process for
continuous integration and delivery
PC5. test, identify, and fix build failures to ensure uninterrupted development and deployment
cycles
PC6. manage deployment policies and processes, ensuring security and compliance are adhered to
in the deployment pipeline
Deployment automation
To be competent, the user/individual on the job must be able to:
PC7. automate application deployment to different environments (e.g., web servers, API services,
databases) using industry-standard tools (e.g., Jenkins, GitLab CI)
PC8. ensure deployment processes are scalable and maintain high availability, using
containerization and orchestration tools (e.g. Docker, Kubernetes)
Knowledge and Understanding (KU)
The individual on the job needs to know and understand:
KU1. different product development life cycles (e.g., Waterfall, Agile, Lean) and their applicability
KU2. different data sources and how to access documents and information from data sources

SSC/N8125: Develop tests or simulations for end-to-end QA of systems
Description
This unit is about designing and developing test or simulation infrastructures to perform end-to-end QA of
functionality, usability, compatibility, security, and/or performance of hardware and software systems that
are supporting the deployment of algorithmic models.
Scope
The scope covers the following :
Define requirements
Create test cases
Run test cases
Conduct performance and load testing
Elements and Performance Criteria
Define requirements
To be competent, the user/individual on the job must be able to:
PC1. define functional requirements of the autonomous system, ensuring clarity and
completeness
PC2. define the type of testing and testing requirements, including unit, sub-system, and system
testing, based on project needs
PC3. identify issues with the requirements for testing and clarify these with relevant stakeholders
PC4. access reusable scenarios, test cases, scripts, and tools from the organization’s knowledge
base
PC5. integrate test cases into the CI/CD pipeline, ensuring smooth transitions from development
to testing
Create test cases
To be competent, the user/individual on the job must be able to:
PC6. create or modify test scenarios relevant to the requirements, ensuring alignment with project
goals
PC7. create or modify software test cases relevant to the requirements, focusing on functionality
and performance
PC8. create or modify hardware test cases relevant to the requirements, covering all necessary
specifications
PC9. identify test cases that can be automated feasibly, optimizing the testing process
PC10. create or modify automated scripts relevant to the requirements, improving efficiency in
testing
PC11. access or create test data relevant to the requirements, ensuring comprehensive coverage
PC12. create a test plan to cover all requirements, detailing scope, objectives, and resources
needed
