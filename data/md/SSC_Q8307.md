SSC/Q8307: Cloud Site Reliability Analyst
Brief Job Description
A Cloud Site Reliability Analyst is responsible for ensuring high availability, scalability, and performance of
cloud-based infrastructure by leveraging automation, observability, and continuous improvement
practices. The individual proactively manage incidents, define SLIs/SLOs, integrate modern DevOps tools,
and contribute to platform resilience using techniques such as chaos engineering and infrastructure as
code.
Personal Attributes
They must possess strong communication skills and interpersonal skills to build relationships. They must
showcase a zeal to learn new things to develop their knowledge and analytical abilities.
Applicable National Occupational Standards (NOS)
Compulsory NOS:
- 1. SSC/N8331: Manage and Maintain Critical Customer-Facing Cloud Services
- 2. SSC/N8330: Automate Cloud Operations and Optimize System Performance

SSC/N8331: Manage and Maintain Critical Customer-Facing Cloud Services
Description
This unit is about monitoring and maintaining mission-critical, customer-facing services and infrastructure,
ensuring high availability, reliability, and performance in line with organizational Service Level Objectives
(SLOs). It also includes troubleshooting, providing technical support, and contributing to incident
management and resolution.
Scope
The scope covers the following :
Monitor systems and ensure availability
Define and track SLIs/SLOs
Diagnose issues and provide technical support
Implement observability and automation
Lead post-incident reviews and improvements
Communicate incident status and manage stakeholder expectations
Elements and Performance Criteria
To be competent, the user/individual on the job must be able to:
PC1. continuously monitor infrastructure, applications, and cloud-native services using
observability tools (e.g., Prometheus, Grafana, Datadog, Cloud Watch)
PC2. monitor and analyze logs, events, and metrics to proactively detect performance bottlenecks
and anomalies
PC3. identify and report unauthorized access attempts and potential security breaches
PC4. manage authentication, authorization, and role-based access control (RBAC) across systems
PC5. escalate critical alerts, incidents, and service degradation issues to relevant stakeholders as
per SLAs
PC6. define meaningful SLIs and SLOs based on product and service expectations
PC7. track error budgets and report on reliability trends
PC8. conduct root cause analysis (RCA) of system failures using log analysis, monitoring
dashboards, and post-mortems
PC9. participate in on-call rotations and assist with service recovery during outages
PC10. document incident handling using standard templates and knowledge base
PC11. contribute to the improvement of runbooks, SOPs, and incident response procedures
PC12. coordinate with development, QA, and infrastructure teams to ensure resolution and
prevention of recurring issues
PC13. integrate observability tools (e.g., ELK stack, Datadog, Prometheus) into cloud infrastructure
PC14. use telemetry data (logs, metrics, traces) to support diagnostics and performance
improvement
PC15. develop automated scripts and workflows for alerting, remediation, and escalation
PC16. conduct root cause analysis and create post-incident review reports

SSC/N8330: Automate Cloud Operations and Optimize System
Performance
Description
This unit is about ensuring high availability, scalability, and performance of cloud-based systems by
implementing automated provisioning, monitoring, and incident response mechanisms. It also includes
creating and maintaining runbooks, defining system KPIs, and driving continuous improvement in system
reliability
Scope
The scope covers the following :
Ensure performance and availability
Monitor and maintain deployed systems
Drive incident management
Elements and Performance Criteria
To be competent, the user/individual on the job must be able to:
PC1. evaluate the health of deployed cloud services to ensure availability and reliability
PC2. automate provisioning and scaling of compute, storage, and networking resources using
infrastructure-as-code (IaC) tools (e.g., Terraform, CloudFormation)
PC3. participate in the change management process to ensure minimal disruption to services
PC4. coordinate and validate software, hardware, and network upgrades or patches to avoid
downtime
PC5. recommend and implement performance tuning and resource rightsizing based on usage
patterns
PC6. design and implement a monitoring strategy for system performance and availability
PC7. define and track key performance indicators (KPIs) and system metrics using monitoring
tools (e.g., Prometheus, CloudWatch, Datadog)
PC8. analyze and interpret logs and metrics to assess system performance and usage trends
PC9. create and update operational runbooks to document standard procedures
PC10. develop scripts and automation workflows to implement runbook steps programmatically
PC11. evaluate and integrate appropriate tools for automation and monitoring from a cost and
functionality perspective
PC12. configure safeguards and automation rules to detect anomalies and trigger alerts
PC13. execute disaster recovery protocols to restore services after system failures
PC14. recommend and implement corrective and preventive actions based on incident trends and
root cause analysis
PC15. Preventive Measures Based on Incident Analysis
PC16. monitor resource usage and identify opportunities for cost reduction (e.g., reserved
instances, autoscaling)
